# Логотипы хостов: интерфейс для архитектора

Рабочий каталог и кандидаты не входят в публичный сайт. Пока архитектор не подтвердит путь, блоки не читают эти файлы и не копируют их в `public/`.

Наличие записи не подтверждает хоста ближайшего выпуска и не делает организацию спонсором. Подписи и расположение блока здесь не задаются.

## Где что лежит

| Что | Путь |
| --- | --- |
| Реестр организаций, кандидатов и пробелов | `data/logos/registry.json` |
| Выбранный набор | `data/logos/selected.json` |
| Применённые экспорты | `data/logos/decisions/` |
| Исходники | `assets-logos/raw/` |
| Подготовленные файлы | `assets-logos/prepared/` |
| Копии выбранных файлов | `assets-logos/selected/<organization_id>/` |
| Каталог выбора | `docs/logos/catalog/index.html` |

`src/content/` этот набор не импортирует. Реестр фотографий не используется.

## Как получить логотип

Читатель для будущего модуля, который подключит архитектор:

```ts
logosFor(organizationId)
```

Сейчас та же функция есть в `scripts/logos/lib/read.mjs` и читает `data/logos/selected.json`.

```js
import { resolvePaths } from "./scripts/logos/lib/paths.mjs";
import { loadSelected, logosFor } from "./scripts/logos/lib/read.mjs";

const item = logosFor(loadSelected(resolvePaths()), "org-agima");
```

Возвращается `null`, если такого `organization_id` нет в принятых данных. Иначе:

| Поле | Смысл |
| --- | --- |
| `name` | Текст из `organizations.ts` |
| `editions` | Московские выпуски, где организация уже была хостом. У участия может быть `label` — подпись этой поездки, как «Яндекс Реклама» в сентябре 2026 |
| `priority` | `first`, `normal`, `reserve` или пусто. Пусто значит, что порядок показа ещё не задан |
| `sort_order` | Порядок внутри группы. Пусто значит, что его не задавали |
| `primary` | Основной файл или `null` |
| `dark` | Версия для тёмного фона или `null` |
| `historical` | Список файлов с `edition_ids`, только если выбор это явно связал |
| `text_fallback` | Название, если логотипа нет |

У файла: `candidate_id`, `src`, `format`, `width`, `height`, `plate`, `variant`. `src` сейчас указывает на `assets-logos/selected/`, не на публичный URL.

Если `primary` пустой, блок показывает `text_fallback` и не подставляет чужой знак.

Порядок в `selected.json`: сначала первая группа, потом обычный показ, потом резерв, потом карточки без приоритета. Внутри группы — `sort_order`, затем название. Приоритет сам не проставляется.

## Выбор

Каталог не пишет реестр. Черновик остаётся в браузере. Экспорт JSON применяется так:

```powershell
node scripts/logos/serve.mjs
node scripts/logos/apply-decisions.mjs путь\к\logos-decisions.json
```

Применение проверяет `organization_id` и `candidate_id`, не затирает решение новее экспорта и копирует только выбранные подготовленные файлы в `assets-logos/selected/`. Повторный поиск организации не сбрасывает уже записанный выбор.

Три состояния в каталоге разделены: сохранено в браузере, экспортировано, применено в реестре.

## Что просим подтвердить

1. Зона логотипов — запрос `docs/requests/2026-11-13-logos-area.md`.
2. Публичный путь выбранных файлов. Пока его нет, в `public/` ничего не кладётся.
3. Имя функции в `src/content/`, если архитектор захочет чтение из секций. Предлагается `logosFor(organizationId)` по образцу `imagesFor()`.
4. Знак Яндекса на публичной странице подчиняется правилам `https://yandex.ru/company/rules/logotype`: ссылка на главную Яндекса и отсутствие намёка на партнёрство. Это ограничение источника, не решение о блоке.

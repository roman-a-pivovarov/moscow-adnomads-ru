# Фотобанк: интерфейс для архитектора и агентов блоков

Сайт берёт кадры только из `data/photobank/published.json` через `imagesFor()`. Агенты не ищут файлы в `assets-raw`, `assets-photobank` или `public/media/photobank` и не делают свои ресайзы.

Файл, который открывается по URL, сам в слайдер не попадает. В блок попадает только запись подборки.

## Как получить подборку

```ts
import { imagesFor } from "../../content/images";
import { coverOf } from "../../content/catalog";

imagesFor("history", edition.id)
imagesFor("program")
imagesFor("hero", edition.id)
imagesFor("home")
imagesFor("hosts")
imagesFor("team", undefined, "person-roman")

coverOf(edition.id)
```

`edition.id` — это `Edition.id`: `2019-moscow-practices`, `2021-moscow`, `2026-moscow-february`, `2026-moscow-may`, `2026-moscow-september`. Человек команды: `person-roman`, `person-irina`.

История всегда с конкретным выпуском. Вызов `imagesFor("history")` без выпуска возвращает пустой список.

Команда фильтруется по `person_id`. У портретов команды `edition_id` пустой: это не кадр поездки, и выпуск им не придумывается.

Общие кадры в подборки московских выпусков не входят.

## Обложка

Отдельного назначения «обложка» нет. Обложка выпуска — первый кадр `imagesFor("history", editionId)`. Фотобанк ставит туда кадр с назначением `history` и приоритетом `primary`. Полароид — оформление сайта, не тип файла и не категория отбора.

`coverOf()` уже читает этот первый кадр. Пока архитектор не подтвердит иное, так и оставляем.

## Приоритет и порядок

Приоритет относится к одному назначению, не ко всем использованиям кадра. Значения: `primary` (основной), `normal` (обычный), `reserve` (резерв).

`published.json` уже отсортирован: назначение, затем выпуск, затем основной, обычный, резерв, затем `asset_id`. `imagesFor()` этот порядок не перемешивает. Резерв идёт после основных и обычных.

Поле `priority` в записи нужно, чтобы порядок можно было прочитать. Сборку оно не пересортировывает.

Статусы «не разобрано» и «не использовать» в подборки не попадают.

Если для блока нет записи, `imagesFor()` возвращает пустой список. Секция остаётся в своём пустом виде. Кадр другого выпуска на это место не подставляется.

Прошедший выпуск не получает `edition_id` будущего выпуска. Герой главной читает только ближайший выпуск. Пока у него нет своих кадров, первый экран остаётся без фотографии, даже если у прошлых выпусков есть назначение `hero`.

## Варианты изображения

Один физический файл на вариант: `public/media/photobank/<asset_id>/<variant>.webp`.

| Вариант | Когда есть | Что берёт сайт |
| --- | --- | --- |
| `thumb` | у каждого обработанного кадра | страница отбора, не слайдеры |
| `web` | у каждого обработанного кадра | история, программа, главная, хосты; герой, если отдельного hero-файла нет |
| `hero` | только у кадров, для которых его отдельно вывели | `imagesFor("hero")` возвращает только такие записи и отбрасывает `web` того же отбора |
| `portrait` | только у портретов команды, которые уже отобраны | `imagesFor("team")` берёт `portrait`, а если его нет — `web` |

Сейчас hero-файлов нет: геройские подборки опубликованы вариантом `web`. Не выводить hero для всех 472 кадров.

Нет нужного файла — записи в `published.json` нет. Пустой `src` и адрес не с корня сайта `imagesFor()` не возвращает.

## Страница отбора

Адрес: `/photo-review/`. Её нет в меню и в sitemap, у страницы `noindex`.

На карточке видны кнопки назначений. Один клик включает назначение и сразу пишет черновик браузера, повторный снимает. Первое назначение ставит статус «Выбрано» и обычный приоритет. Звёздочка у активного назначения делает его основным и повторным кликом возвращает обычный. «Обложка тура» ставит этому кадру приоритет `primary` у `history` и снимает этот признак с прежней обложки того же выпуска. Принадлежность выпуску при этом не меняется. «Не использовать» снимает назначения.

Страница статическая. Она не пишет реестр. Черновик остаётся в браузере. Экспорт JSON применяется командой:

```powershell
node scripts/photobank/apply-decisions.mjs путь\к\photobank-decisions.json
```

Экспорт содержит `asset_id`, решения и версию набора. Применение проверяет неизвестные id и не затирает решение новее экспорта. Меняются только переданные поля. После применения каталог и `published.json` собираются из реестра заново.

Фильтр «Предложено бильд-редактором» показывает стартовый отбор. Это не ручное решение Романа.

## Внутренний реестр

`data/photobank/registry.json` — источник решений. Подборки из него производятся, отдельно их не правят.

```powershell
node scripts/photobank/query.mjs msk-000001
node scripts/photobank/query.mjs --edition=2019-moscow-practices --status=selected --placement=history
```

`original` в ответе — неизменённый файл, не для сайта. `editorial` при импорте не меняется.

## Деплой

На FTP уходит `./dist/` после сборки. Оригиналы, ZIP, `assets-inbox`, `assets-raw`, `assets-work`, временные PNG и `scripts/photobank/.venv` в git-пакет публикации, `public/` и `dist/` не входят. Рабочие WebP в `assets-photobank/` остаются в репозитории и не копируются в `dist/`: на сайт попадают копии из `public/media/photobank/`.

## HEIC

Настоящий HEIC/HEIF читается декодером Python в `scripts/photobank/.venv`. JPEG и PNG идут через sharp. Файл с расширением `.HEIC`, внутри которого JPEG, обрабатывается как JPEG. Установка: `docs/photobank/install-windows.md`.

Временный PNG удаляется после кадра. Оригинал остаётся в `assets-raw`.

## Принято архитектором, 2026-11-12

- Сайт не импортирует `registry.json` и не ссылается на сырьё.
- Отобранный кадр фотобанк записывает в `data/photobank/published.json` и кладёт файл в `public/media/photobank/<asset_id>/<variant>.webp`.
- Схема записи: `asset_id`, `edition_id`, `person_id`, `placement`, `variant`, `src`, `width`, `height`, `alt`, `caption`. Поле `priority` добавлено рядом, чтобы порядок был виден; подтверждение запрошено отдельно.
- Для `history` вызов без выпуска ничего не возвращает. Если варианта `hero` нет, страница берёт `web` того же отбора.
- Архивный кадр не назначается портретом и не назначается составом будущего выпуска.
- Корень репозитория на FTP не возвращаем.
